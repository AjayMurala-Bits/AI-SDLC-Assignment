## Experiment A — baseline

Request format:

```json
{"type":"json_object"}
```

The raw response was well-formed JSON with exactly the five required fields.
The parsed sentiment was lowercase `mixed`, which is allowed by the schema but
does not match this case's expected `negative` classification. The output also
introduced unsupported positive aspects and recommendation language, but this
experiment did not invoke the semantic judge.

Application result: schema-valid, property expectation not satisfied.

## Experiment B — schema enforcement

Request format:

```json
{
  "type": "json_schema",
  "json_schema": {
    "name": "movie_review_summary",
    "strict": true,
    "schema": "the unchanged application success_schema()"
  }
}
```

Ollama accepted the schema request through the OpenAI-compatible endpoint; no
API compatibility error was recorded. The raw response parsed successfully
and contained the five required fields, valid arrays, strings and a valid
sentiment enum value. It returned lowercase `mixed`, not the expected
`negative`. It also added unsupported content such as “good cinematography”,
“engaging performances” and “plot holes”; semantic judging was intentionally
not run.

Application result: schema-valid, property expectation not satisfied.

## Interpretation

Schema enforcement was accepted and produced a schema-valid response, but it
did not improve application validation in this paired run because baseline A
also happened to produce a schema-valid response. It did not improve semantic
correctness: both experiments failed the independent expected-sentiment check.

This is expected from the current schema: it constrains the sentiment to one
of `positive`, `negative`, `mixed`, or `unclear`, but it cannot require the
case-specific expected value `negative`. Case-level sentiment correctness
remains a deterministic property/evaluation rule.

The two requests were sequential local generations and no temperature was
explicitly set, so output differences between future A/B runs may include
model sampling variance. This experiment therefore establishes feasibility and
one observed result, not a statistical superiority claim.

Ollama's official documentation supports supplying a JSON Schema through the
structured-output `format` parameter and states that structured outputs also
work through the OpenAI-compatible API via `response_format`:

- https://github.com/ollama/ollama/blob/main/docs/capabilities/structured-outputs.mdx
- https://github.com/ollama/ollama/blob/main/docs/api.md

## Recommendation before any repair

Do not change the frozen dataset, prompts, thresholds or provider permanently.
The smallest defensible next step is to review this result and, if approved,
make only the Ollama application adapter use the exact schema request by
default, while retaining application validation. Add telemetry and raw-output
capture to the normal runner separately. A later focused diagnostic should
also set a documented deterministic sampling setting if supported, then repeat
the same A/B comparison before any full evaluation.
