## Repair applied

### Sanitized provider diagnostics

[`provider.py`](../../src/movie_review_summarizer/provider.py) now classifies provider exceptions without serializing messages, request data, keys or headers. It records only:

- `authentication`
- `quota_billing`
- `rate_limit`
- `connection`
- `timeout`
- `malformed_response`
- `unknown`

When available, a numeric `status_code` and constrained safe `error_code` are retained. [`application.py`](../../src/movie_review_summarizer/application.py) keeps the public failure shape unchanged and passes diagnostics separately to the runner. The live evidence report can now distinguish application failure from provider/service classification without exposing sensitive details.

### Deterministic fixture handling

[`runner.py`](../../src/movie_review_summarizer/evaluation/runner.py) now:

- leaves the `MISS-001` path uncreated so it exercises a genuine missing-file failure;
- writes invalid bytes for invalid-encoding fixtures;
- executes `SVC-001` as a deterministic simulated service failure without an API call;
- executes `OUT-001` as a deterministic simulated malformed-output failure without an API call;
- records `fixture_mode`, `simulated`, `provider_error`, and `judge_error` per case;
- labels offline cases `offline-mock` and simulated live cases explicitly.

The fixture changes do not alter the frozen dataset or expected outcomes.
