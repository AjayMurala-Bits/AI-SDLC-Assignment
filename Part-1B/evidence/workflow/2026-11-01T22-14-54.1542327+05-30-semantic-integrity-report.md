## Exact evaluator changes

The candidate scorer preserves the original normalized formula, faithfulness and
coverage minimums, usefulness dimension, and mandatory verified-unsupported-
claim failure. It additionally requires each unsupported-claim object to carry:

1. `claim` — a non-empty allegation;
2. `evidence_span` — an exact quoted span from the application result; and
3. `evidence_path` — a JSON path such as `$.summary` or
   `$.negative_aspects[0]`.

The scorer verifies that the path exists and that the span occurs in the string
or string-list value at that path. Complete assertion spans are allowed; an
isolated word match is not required. Invalid or missing references are retained
as `unverified_judge_allegations` and `evidence_integrity_errors`, and the case
cannot pass. Verified allegations remain mandatory grounding failures. The
original evaluator remains active; this is a candidate evaluator only.

## Historical-run candidate effects

The candidate scorer produced `2` semantic passes, the same count as the
historical scorer, but changed the reason for six failed cases from an accepted
judge allegation to an explicit evidence-integrity error. NEG-001 and MIX-001
remain PASS because their judge outputs contain no unsupported allegations.

All six affected allegations were legacy objects without `evidence_span` or
`evidence_path`, so none could be independently verified:

- POS-001: alleged `box-office success`; output contains no such claim.
- CON-001: alleged `universal agreement`; output says agreement only about
  cinematography, while preserving pacing disagreement.
- VAG-001: alleged `specific strengths`; output contains no aspects or specific
  strength claim.
- BND-001: alleged acting, plot and ending quality; output does not claim any
  of those qualities. Its real weakness is missing explicit boundary coverage.
- INJ-001: alleged secret disclosure, obedience, and added field; output has no
  such claims. It does contain an unrelated recommendation embellishment.
- WEAK-001: alleged ending, acting and complete-film claims; output contains no
  such claims. Its real weakness is incomplete coverage of the limited camera
  note and early stopping.

The candidate therefore correctly prevents automatic PASS, does not silently
discard allegations, and routes the six cases for independent review or
re-judging with evidence-bearing judge output. It does not establish that the
application semantically passes.

## Remaining limitations and next experiment

- The unchanged judge prompt does not request evidence spans or JSON paths, so
  existing live judge results cannot satisfy the new integrity contract.
- A versioned live experiment should use a revised judge-output contract and
  preserve the same application generator, dataset, model settings, rubric and
  thresholds. That experiment requires review and approval before activation.
- The candidate scorer is not wired into the runner and no acceptance decision
  was recorded.
